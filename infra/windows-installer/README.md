# Нативный установщик: кандидат, не публичный выпуск

`Build-Installer.ps1` компилирует x64 WinForms bootstrap штатным C#-компилятором Windows с проверкой его Microsoft Authenticode. Встроенный ZIP должен совпасть с release.json по версии, размеру и SHA-256. Публичный ZIP не пересобирается и не заменяется.

Без аргументов EXE запрашивает UAC, извлекает проверенный payload в новый закрытый каталог Program Files с доступом Administrators/SYSTEM и открывает существующий мастер. Данные и код установленного сервера не перезаписываются bootstrap-ом; установкой службы управляет прежний мастер. Ошибки показываются в окне. Одноразовые каталоги исходников сохраняются для журналов; политики их очистки и полноценный uninstall ещё требуют завершения.

Диагностические режимы не требуют UAC:

- `--verify <new-report.json>` проверяет SHA-256, структуру, имена, размер и версию встроенного ZIP без распаковки/запуска процессов.
- `--extract-test <new-directory> <new-report.json>` распаковывает встроенный ZIP в новый каталог без запуска установщика.
- `--preview <new-image.png> <new-report.json>` показывает и закрывает только стартовое окно, сохраняя его изображение; это не проверка мастера, UAC или службы.

Запуск диагностических режимов также может блокироваться политикой подписи Windows. Строитель фиксирует такую ошибку, не помечая артефакт проверенным.

## Фактический результат 18 ноября 2026

Кандидат с payload0.4.43 скомпилирован, но его первый `--verify` не был допущен Windows к исполнению. CodeIntegrity3077/3033 подтвердили блокировку по политике `{0283ac0f-fff1-49ae-ada1-8a933130cad6}`. Статус Authenticode NotSigned. Проверка payload внутри EXE, распаковка, GUI, UAC и переход к мастеру **не приняты**. Отчёт находится вне дистрибутива: work/native-installer043-result.json.

Нет автоматически установленного самоподписанного сертификата, исключений Defender, изменений политик Windows или удаления интернет-метки. Исходный PowerShell flow сохранён; это означает, что собственные PowerShell-файлы также надо включить в план подписи. Подписанный внешний EXE сам по себе не делает их подписанными. После подписи payload нужен новый точный SHA-256 и новая сборка bootstrap, затем подпись самого EXE, повторная приёмка и метаданные окончательного файла.

Автоматическая публикация кандидата отсутствует. Перед выпуском требуются доверенная подпись с временной меткой, проверка подписанных байтов, запуск из настоящего скачанного файла и чистая Windows. Даже успешная Authenticode-проверка не является гарантией репутации SmartScreen.
