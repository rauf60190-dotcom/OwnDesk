# OwnDesk

Перед установкой: [рекомендации по компьютеру сервера](docs/HARDWARE-REQUIREMENTS.md). Сервер устанавливается один раз для организации; сотрудники работают через браузер.

[Code signing policy](docs/CODE-SIGNING-POLICY.md) — статус подписи, сборок и одобрения выпусков.

Собственный код — [MIT](LICENSE); [сторонние лицензии](LICENSING.md) сохраняют свои условия. [Сборка из исходников](docs/SOURCE-DEVELOPMENT.md), [сообщения об уязвимостях](SECURITY.md), [автоматические проверки](https://github.com/rauf60190-dotcom/OwnDesk/actions/workflows/verify.yml). Windows-подпись пока не подключена; изменения исходного кандидата ещё не входят в опубликованный 0.4.43.

Сервис для обработки обращений из Telegram. Оператор работает с очередью, берёт обращение, ведёт переписку, оставляет внутренние заметки и фиксирует результат решения. История переписки, действий и сроков хранится на сервере.

## Посмотреть на Windows

Для Linux Compose доступны [резервные копии, изолированная проверка восстановления и расписание](docs/LINUX-BACKUPS.md).

Для совместимых Linux-сборок — [обновление и откат без возврата старой базы](docs/LINUX-UPDATES.md).

Для новой организации с PostgreSQL и службой Windows используйте предварительный `Setup-OwnDesk-Server.cmd`: [инструкция и ограничения](docs/WINDOWS-SERVER-INSTALLER.md). Он сам подготавливает подписанный Python; нужны права администратора и интернет. Описанный ниже `Setup-OwnDesk.cmd` сохраняет прежний локальный запуск.

Распакуйте архив целиком и откройте `Setup-OwnDesk.cmd` двойным щелчком. Для первого запуска нужны Python 3.12 с Tkinter и интернет. Откроется отдельное тёмно-синее окно OwnDesk с состоянием подготовки. Оно создаёт окружение и открывает браузер после готовности сервера, передавая мастеру одноразовый код. Код удаляется из адресной строки после открытия мастера.

Окно запуска должно оставаться открытым, пока вы работаете. В нём доступны кнопки «Открыть мастер», «Открыть журнал» и повторная попытка после сбоя. `Setup-OwnDesk.cmd` не требует разрешения на выполнение сценариев PowerShell. Ошибка остаётся в окне; подробности сохраняются в `.runtime/startup.log`. Если в выбранном Python нет Tkinter, доступен запасной запуск в консоли.

Мастер оформлен в тёмно-синем стиле OwnDesk. Укажите название организации, часовой пояс, имя владельца, email и пароль. Затем можно ввести код из раздела «Мои установки» на портале, чтобы привязать сервер к аккаунту. В конце мастер проверяет базу и вход и открывает рабочее пространство.

Для запуска из PowerShell используйте следующую команду.

```powershell
.\Start-OwnDesk.ps1 -OpenBrowser
```

Адрес показан в окне запуска и сохранён в `.runtime/local-port`. Если порт 5173 занят другой установкой, выбирается свободный порт — занятый сервер не останавливается. При ручном открытии этого адреса мастер запросит код из `.runtime/installation-code.txt`. Существующая организация открывается с прежними аккаунтами и данными. Закрытие окна подготовки останавливает только созданное им дерево процессов. Этот локальный запуск работает в пользовательском процессе. Для фоновой службы и публичного адреса используйте `Setup-OwnDesk-Server.cmd`; сведения о раздельных службах портала и организации — в [инструкции по службам Windows](docs/WINDOWS-SERVICES.md).

Локальный запуск поддерживает текстовую переписку с настоящим Telegram-ботом через getUpdates, без домена и внешнего webhook. Под администратором откройте «Настройки → Telegram → Подключить бота» и введите токен отдельного бота. Клиент должен написать боту описание проблемы. Оператор открывает новое обращение в «Свободных», нажимает «Взять в работу» и отправляет ответ. Держите приложение запущенным. У ручных демонстрационных карточек нет адресата Telegram. В локальном режиме файлы сохраняются в .runtime/private-attachments и выдаются через API с проверкой прав. При переносе установки скопируйте также этот каталог. Рабочая конфигурация Compose использует закрытый S3-бакет. Ключ расшифровки токенов находится в .runtime/telegram.key рядом с локальной базой; сохраните их вместе при переносе установки.

## Рабочая установка через Docker Compose

Для Ubuntu Server 24.04 LTS x86-64 доступен [Linux-установщик](docs/LINUX-INSTALLER.md): `sudo bash Setup-OwnDesk.sh`. На чистой Ubuntu в Hyper-V проверены установка, подключение через домен OwnDesk, приглашения, переписка, фото/видео и автоматический запуск после перезагрузки. Другие дистрибутивы и ARM пока не входят в проверенную матрицу.

Для одной организации также доступен [нативный рабочий режим](docs/NATIVE-RUNTIME.md) с PostgreSQL, одним ASGI-процессом и закрытым файловым хранилищем. Он работает без Docker и Redis. Для Windows доступен предварительный [установщик рабочего сервера](docs/WINDOWS-SERVER-INSTALLER.md).

Для установки организации понадобятся Linux-сервер с Docker Engine и Compose v2, домен с доступными портами 80 и 443 и закрытый S3-совместимый бакет. Первого владельца создаёт мастер настройки с одноразовым кодом. Сотрудники присоединяются по приглашениям. Порядок запуска, проверки HTTPS и приёмки описан в [инструкции для Linux](docs/LINUX-DEPLOYMENT.md).

## Подключить Telegram

1. Создайте тестового бота в BotFather. Войдите в OwnDesk администратором и откройте **Настройки → Telegram → Подключить бота**.
2. Введите токен и выберите команду. Сервер проверит бота через `getMe`, зашифрует токен и зарегистрирует webhook на `PUBLIC_BASE_URL`. После сохранения токен не возвращается браузеру.
3. В личном чате отправьте `/start`, затем описание проблемы. Проверьте «Свободные». Нажмите «Взять», отправьте ответ и проверьте его в том же Telegram-чате.
4. Для испытания групп добавьте бота в тестовую группу. Обеспечьте получение нужных событий через права бота или настройку Privacy Mode. После первого события подтвердите группу в **Настройки → Группы** и выберите режим обработки.
5. В теме общей группы отправьте `/new Описание проблемы`. Ответ из карточки должен попасть в исходный `chat_id` и `message_thread_id`. При ответе на конкретное сообщение также передаётся `reply_parameters`.

Если webhook требует внимания, проверьте внешний HTTPS, DNS, состояние worker и `GET /api/v1/integrations/{id}/health`. Этот же ресурс поддерживает `PATCH` для замены токена того же бота, переустановки webhook и ручного отключения. Для ограничений групп и типов файлов используйте официальную документацию. [Telegram Bot API](https://core.telegram.org/bots/api) · [Bots FAQ](https://core.telegram.org/bots/faq)

## Кабинет клиента

Клиент получает персональную ссылку, создаёт веб-обращения, добавляет файлы и получает ответы. Сотрудники отвечают из обычной очереди. См. [инструкцию по кабинету поддержки](docs/CUSTOMER-SUPPORT.md).

## Доска тикетов

Статусы показаны в колонках, а маршрут L1 → L2 → L3 → разработчики отображается на карточках. См. [настройку доски и эскалаций](docs/TICKET-BOARD.md).

## Работа оператора

Нажмите «Запросы» для раскрытия очередей. В «Свободных» выберите обращение и нажмите «Взять в работу». Список поддерживает поиск по номеру, теме, клиенту, чату и переписке. Фильтры и сортировка сохраняются в URL. «Колонки» добавляет команду и даты. Условия поиска можно сохранить как личный фильтр.

В карточке выберите «Ответ клиенту» или «Внутренняя заметка». Черновики этих режимов разделены. Статус «В очереди» означает, что сервер принял сообщение. «Отправлено в Telegram» появляется только после подтверждения Telegram. При неизвестном результате сначала проверьте исходный чат. Ручной повтор требует подтверждения риска дубликата.

Когда задача выполнена, выберите «Решено» и укажите результат. «Закрыто» — отдельное последующее действие. История действий показывает назначения и изменения статусов. «Общий чат» открывает только доступную переписку. Входящие сообщения можно выбрать и выделить в отдельное обращение.

### Настроить рабочее время SLA

Откройте «Настройки → SLA → Расписание и пересчёт» у нужного приоритета. Отключите 24/7, выберите рабочие дни и часы. Для перерыва добавьте два непересекающихся интервала. В «Праздники и особые дни» укажите конкретную дату и выходной либо особые часы. Используется часовой пояс пространства. Сохранение влияет на новые сроки; для текущих обращений предусмотрен отдельный пересчёт с подтверждением.

### Регистрация и портал

Сервер организации принимает сотрудников по приглашениям. Для отдельного локального портала владельцев запустите `Start-Portal.ps1` в другом PowerShell и откройте http://127.0.0.1:5175. Портал использует другую базу, создаёт только аккаунты и показывает тестовые письма. Настройка режимов: [DEPLOYMENT-MODES.md](docs/DEPLOYMENT-MODES.md).

Подготовка отдельного адреса, рабочее окружение и запуск защищённого коннектора описаны в [инструкции туннелей](docs/INSTALLATION-TUNNELS.md). Команда `run_connector` контролирует выделенный `cloudflared` и включает рабочий маршрут после проверки HTTPS и готовности сервера. Обычный `Setup-OwnDesk.cmd` работает локально; `Setup-OwnDesk-Server.cmd` автоматически подготавливает рабочее окружение и службу Windows для новой организации.

### Пригласить сотрудника

Откройте «Настройки → Сотрудники», заполните email, роль и команду и создайте приглашение. Скопируйте ссылку и передайте сотруднику лично. Она действует 72 часа. При настроенном SMTP можно выбрать отправку приглашения по почте. Сотрудник задаёт собственный пароль и входит по email. Владелец организации выделен в списке; назначать администраторов может только он. План дальнейших этапов: [ROADMAP.md](docs/ROADMAP.md).

### Безопасность аккаунта

В профиле сотрудника и кабинете портала доступны TOTP, резервные коды, активные сессии и события безопасности. Восстановление пароля открывается по кнопке «Забыли пароль?». Для реальной почты нужен SMTP; тестовые ссылки доступны только локальным тестовым аккаунтам. Сохраняйте ключи account-security.key / portal-security.key вместе с базами. Подробности: [ACCOUNT-SECURITY.md](docs/ACCOUNT-SECURITY.md).
