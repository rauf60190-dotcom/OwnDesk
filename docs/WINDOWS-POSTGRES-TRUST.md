# Восстановление PostgreSQL при блокировке Windows

20 ноября 2026 Code Integrity заблокировал `libpq.dll` из EDB PostgreSQL 17.11-3 в `pg_ctl.exe` и Python. Код отказа утилиты — `0xC0E90002`. PostgreSQL оставался работать после отказа клиентской библиотеки; последующие запуски OwnDesk останавливались из-за занятых портов.

## Проверенный комплект

Использован официальный [EDB PostgreSQL 17.12-1 Windows x64](https://get.enterprisedb.com/postgresql/postgresql-17.12-1-windows-x64-binaries.zip). EDB описывает добавление подписей EXE и DLL в [журнале выпуска 17.12-1](https://github.com/EnterpriseDB/edb-installers/blob/REL-17/changes.md).

- Размер скачанного архива: 386263884 байта.
- Локальный SHA-256: `a2cd8a774389347b70be7748ac4a37ef43cb6ee539c5fc3e85ae264b15e4a04c`.
- Отдельная контрольная сумма издателя на странице загрузок не предоставлена; локальный хеш фиксирует использованные байты и не выдаётся за хеш издателя.
- Проверены 159 EXE/DLL в `pgsql/bin` и `pgsql/lib`: Authenticode Valid, издатель EnterpriseDB Corporation.
- На этом ноутбуке с прежней защитой Windows проверены загрузка libpq 170012, запуск PostgreSQL 17.12, синтетическая запись, PL/pgSQL, dump/restore и штатная остановка. Рабочие базы в изолированном прогоне не открывались.

## Применение к существующим службам

Серверные файлы скопированы в отдельные каталоги `runtime/tools/postgresql-17.12-1` с правами чтения соответствующей службы. Исходные EXE/DLL 17.11-3 сохранены; одинокие библиотеки между комплектами не смешивались. Оригинальные файлы лицензий поставщика сохранены вместе с новым комплектом.

До остановки баз сделаны логические копии каждой базы и проверено чтение оглавления pg_restore. Сохранены конфигурация, ключи и приватные файлы. После штатной остановки сделаны холодные копии `pgdata`; содержимое файлов сверено по SHA-256. Копии находятся в защищённом административном каталоге OwnDesk Backups. Это резервные копии перед ремонтом, а не новый общий формат мастера восстановления.

В рабочих `runtime-profile.json` изменён только путь `postgres.bin`. Версии приложения, аккаунты, пароли, ключи и настройки интеграций не менялись. Обновления схемы OwnDesk в эту операцию не включались. Отключение Windows Code Integrity, снятие интернет-меток и принудительное завершение PostgreSQL не использовались.

После перехода проверены обе службы, HTTP health локально и через публичный HTTPS (200), один штатный stop/start каждой службы с освобождением её портов, неизменность закрытых настроек и файлов вложений, количество основных деловых записей и отказ личного API гостю (JSON 403). Служебный файл `native-server.worker.lock` исключён из хеширования работающих вложений: он блокируется живым процессом и не является пользовательским файлом. Обе службы остались Running после проверок.

## Граница результата

Ремонт действующих служб не заменяет приёмку нового установщика. Опубликованный OwnDesk 0.4.43 остаётся прежним. В исходниках кандидата 0.4.44 pin обновлён на PostgreSQL 17.12-1 с указанными выше размером и SHA-256. Собраны уведомления о лицензиях точного нового архива; прежний инвентарь и тексты 17.11-3 сохранены. Установщик извлекает оригинальные `server_license.txt` и `commandlinetools_3rd_party_licenses.txt` вместе с runtime.

На этом ноутбуке новая подготовка зависимостей проверила 1574 установленных файла, совпадение 159 подписанных EXE/DLL с проверенным комплектом, сохранность двух файлов лицензий и отсутствие pgAdmin. Настоящая загрузка pg_ctl и psycopg/libpq прошла до запуска базы. В Windows CI добавлена отдельная обязательная проверка подписей всего `bin` и `lib` до запуска тестовой службы. Доверенность других компонентов, подпись самого OwnDesk и установка на чистом компьютере остаются отдельными проверками.

В кандидат исходников добавлена проверка загрузки pg_ctl и psycopg/libpq **до** инициализации или запуска базы. Она предотвращает повторение части отказа с оставшимся процессом базы; сама по себе эта проверка не делает неподписанную библиотеку доверенной. В рабочие файлы приложения это изменение ещё не устанавливалось.
