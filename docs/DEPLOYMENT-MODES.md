# Портал и сервер организации

Одна кодовая база поддерживает два самостоятельных режима. Каждый запускается отдельным процессом, со своей базой, секретами и адресом. В рабочей среде используются отдельные базы PostgreSQL, отдельные Redis/очереди и независимые ключи сессий. Общая рабочая база для портала и организации не поддерживается.

## Сервер организации

DEPLOYMENT_MODE=organization. Открытая регистрация и Google-вход закрыты даже при PUBLIC_REGISTRATION_ENABLED=1. Владелец создаётся при первоначальной настройке; сотрудники присоединяются по приглашениям. Рабочие запросы не обращаются к центральному порталу. Telegram и сотрудники подключаются напрямую к серверу организации.

На Windows запустите Start-OwnDesk.ps1. Адрес: http://127.0.0.1:5173, база: .runtime/demo.sqlite3 (прежнее имя оставлено для совместимости). Существующие организации, аккаунты и чаты сохраняются. Мастер настройки для них недоступен.

На новой установке скрипт создаёт .runtime/installation-code.txt. Откройте этот файл локально и введите код в мастер вместе с названием организации, именем, email и паролем владельца. Код действует 24 часа и используется однократно. Не отправляйте файл сотрудникам и не публикуйте его. На Windows проверьте, что каталог доступен только владельцу установки/администратору ОС.

Для перевыпуска кода до завершения настройки:

```
python manage.py prepare_installation --output /private/path/installation-code.txt --rotate
```

После создания организации код больше не даёт доступа к настройке. Введение адреса при настройке не считается подтверждением владения email. Для рабочей конфигурации нужны независимые секреты, HTTPS и PostgreSQL. Публичную регистрацию на сервере организации не включать.

## Центральный портал

Для публичного запуска см. [настройку портала OwnDesk](OWNDESK-PORTAL.md).

DEPLOYMENT_MODE=portal. Регистрация создаёт только аккаунт, без Workspace, Membership, команд и SLA. Кабинет показывает назначение портала и порядок установки. API обращений, файлов, сотрудников, интеграций и приглашений закрыты, WebSocket рабочих событий отклоняется. Локальный обработчик Telegram не запускается.

На Windows запустите Start-Portal.ps1 в отдельном PowerShell. Адрес: http://127.0.0.1:5175. База: .runtime/portal.sqlite3; ключ сессий: .runtime/portal-session.key. Имя cookie отличается от сервера организации. Локальный портал показывает тестовые письма; настоящие SMTP и Google OAuth пока не настроены.

Аккаунты портала и сервера организации независимы. Вход на портал не предоставляет доступ к установке организации. Текущие рабочие данные никуда не переносятся и не копируются.

В кабинете есть скачивание версии для Windows и шаги установки. Для публикации администратор размещает согласованные `OwnDesk.zip` и `release.json` в закрытом каталоге и задаёт `PORTAL_RELEASE_DIR` процессу портала. Для локального запуска каталог по умолчанию — `.runtime/releases`. Для Compose смонтируйте каталог в контейнер портала только для чтения и укажите путь внутри контейнера. Метаданные и архив выдаются после входа. Портал сверяет размер и SHA-256 перед выдачей. При обновлении рекомендуется подготовить отдельный каталог выпуска и переключить настройку после проверки.

Каталог зарегистрированных установок и привязка к порталу остаются отдельным этапом.

## Демонстрационный режим

DEPLOYMENT_MODE=demo разрешён только с DEBUG. Старый объединённый сценарий регистрации оставлен для тестов. На Windows запускается явно: Start-OwnDesk.ps1 -Mode demo. Это не рабочая архитектура публичного продукта.

## Проверки этапа

68 серверных тестов прошли, 2 требуют PostgreSQL. Проверены запрет регистрации на сервере организации, недоступность рабочих API на портале, одноразовый код, истечение кода, CSRF и запрет повторной настройки. Браузер на отдельных базах проверил первоначальную настройку, регистрацию на портале, одновременные сессии и ширину 390 px. Проверка реального домена и производственной инфраструктуры остаётся отдельным этапом.
