# Резервные копии Linux Compose

В 0.4.34 добавлены штатные команды для установки через `Setup-OwnDesk.sh` на Ubuntu 24.04 amd64. Нужны существующие Python 3, Docker и Compose. Копия включает PostgreSQL dump, вложения, ключи, привязку установки и `.runtime/linux`.

## Размещение

Постоянный каталог программы, конфигурация и их родители должны принадлежать root. Для свежей установки, распакованной в `/opt/OwnDesk`, при необходимости исправьте владельца и права:

```sh
sudo chown -R root:root /opt/OwnDesk
sudo chmod -R go-w /opt/OwnDesk
cd /opt/OwnDesk
```

Эти команды относятся к программе. Владельца томов PostgreSQL и медиа вручную не меняйте. Каталоги копий имеют права 0700, файлы — 0600. Копии содержат секреты и самим инструментом не шифруются; для внешнего хранения используйте шифрование с отдельно сохранённым ключом.

## Создание и проверка

```sh
sudo bash OwnDesk-Backup.sh backup --output-dir /var/backups/owndesk
sudo bash OwnDesk-Backup.sh verify \
  --input /var/backups/owndesk/backup-YYYYMMDDTHHMMSSZ-id
```

`backup` возвращает JSON с `status: verified` и путём новой копии, существующие каталоги не перезаписываются. Приложение ненадолго останавливается для согласованного снимка. База остаётся включённой; если она была выключена, запускается только для копирования. После операции восстанавливается исходное состояние обоих контейнеров. Выключенное приложение не запускается.

Версия копии берётся из реально установленного образа. Инструмент 0.4.34 может скопировать установку 0.4.33. `verify` проверяет состав, размер и SHA-256 файлов, закрытые права и отсутствие ссылок. Хеши обнаруживают повреждение, но не удостоверяют происхождение копии. Неполный каталог без итогового манифеста не считается успешным.

Старые и неполные копии автоматически не удаляются. Контролируйте свободное место и храните отдельную копию на другом защищённом носителе.

## Изолированное восстановление

```sh
sudo bash OwnDesk-Backup.sh restore-check \
  --input /var/backups/owndesk/backup-YYYYMMDDTHHMMSSZ-id
```

Создаются отдельные тома и внутренняя сеть Docker. PostgreSQL работает без root и дополнительных capabilities, с файловой системой контейнера только для чтения и без опубликованных портов. Сама копия не монтируется в PostgreSQL. Сверяются строки всех таблиц, хеши восстановленных файлов, ключи и ограниченная роль приложения.

Приложение, коннектор, Telegram и почта из копии не запускаются. Рабочие данные не заменяются. После проверки временные контейнер, сеть и тома удаляются; при обычной ошибке выполняется та же очистка. Закрытый диагностический журнал остаётся рядом с копиями. Переключение восстановленных данных в рабочий режим пока не реализовано.

Нужны **исходные Docker-образы**, указанные в манифесте. Они не включаются в каждую копию данных. Для проверки на другом сервере отдельно сохраните образы через `docker image save`, загрузите через `docker image load` и сохраните соответствующий дистрибутив OwnDesk. По указанию копии инструмент не скачивает произвольные образы.

## Ежедневное расписание

```sh
sudo bash OwnDesk-Backup.sh schedule \
  --output-dir /var/backups/owndesk --at 02:30
```

Время задаётся **в часовом поясе сервера** (`timedatectl`), со случайной задержкой до пяти минут. systemd timer учитывает пропущенное срабатывание при выключенном сервере. Расписание включается только этой командой; обычная установка его не включает. Код расписания должен принадлежать root и быть недоступен для записи другим пользователям.

Имя таймера содержит ID Compose-проекта и возвращается в JSON:

```sh
systemctl status owndesk-backup-XXXXXXXXXXXX.timer
journalctl -u owndesk-backup-XXXXXXXXXXXX.service
sudo bash OwnDesk-Backup.sh unschedule
```

`unschedule` удаляет только собственные файлы systemd, не удаляет копии и не прерывает выполняющуюся операцию. Дополнительно создаётся служба восстановления состояния при загрузке; `ExecStopPost` вызывает тот же механизм после прерванной задачи. Установщик и копирование используют общую блокировку.

## Прерывание

Перед остановкой сохраняется журнал с прежним состоянием и точными ID контейнеров. Если задача прервана и расписание не настроено:

```sh
sudo bash OwnDesk-Backup.sh resume
```

Команда возвращает существующие контейнеры к прежнему состоянию; старую БД не восстанавливает и неполную копию не продолжает. Пока журнал не обработан, установщик отказывается менять эту установку.

## Приёмка

На отдельной Ubuntu VM проверены реальные команды, работающая тестовая установка и сохранение выключенного состояния прежней организации. В отдельной базе восстановлены 42 таблицы и пять медиафайлов. Проверены отказ при повреждении, очистка после неуспешного PostgreSQL restore, восстановление после SIGKILL процесса копирования, регистрация таймера и ручной запуск его службы. Тестовое расписание затем отключено. Обесточивание физического сервера и ночное календарное срабатывание отдельно не проверялись. Для совместимых служебных сборок в 0.4.35 добавлены [команды обновления и отката](LINUX-UPDATES.md).
