# Самостоятельная установка организации

Целевой сценарий: владелец скачивает OwnDesk, запускает установщик, указывает организацию и владельца, привязывает свой кабинет и получает проверенный HTTPS-адрес. Данные и ключи организации остаются на её компьютере.

## Первый блок: автоматическая подготовка адреса, 0.4.19

После привязки коннектор может запросить конфигурацию без предварительной команды администратора `prepare_public_route`. Портал проверяет ключ именно этой установки, создаёт туннель и DNS, восстанавливает частично завершённую операцию при повторном запросе. Отозванные подключения и отозванные маршруты не восстанавливаются. Общий ключ Cloudflare не передаётся на компьютер организации.

В мастере доступна кнопка «Подготовить адрес организации». Запрос выполняется сервером организации и сохраняет только назначенный hostname рядом с закрытым ключом привязки. Выданный токен запуска туннеля в настройки мастера не записывается и браузеру не возвращается. Мастер различает привязку аккаунта, подготовленный адрес и реально подтверждённый публичный доступ.

В режиме рабочего сервера `run_connector` выполняет этот шаг автоматически при первом запросе конфигурации. Команда `connect_portal --state ... --once --prepare-route` позволяет выполнить только подготовку адреса без запуска туннеля. Основной пользовательский путь этого шага — кнопка в мастере, ручная команда не обязательна.

Адрес сначала закрыт. Затем разрешён только endpoint проверки. Полный рабочий интерфейс включается после подписанного подтверждения через HTTPS. Локальный мастер не помечает организацию доступной сотрудникам из интернета только по факту создания аккаунта или DNS.

## Текущее состояние и следующие блоки

В 0.4.24 [рабочий установщик Windows](WINDOWS-SERVER-INSTALLER.md) автоматически подготавливает подписанный Python, PostgreSQL, Caddy и cloudflared. Проверены отдельное окно, запрос кода после подготовки зависимостей и настоящая служба LocalService с остановкой, повторным запуском и восстановлением после сбоя. Данные и код размещаются раздельно. [Подготовка Python](PYTHON-BOOTSTRAP.md).

Общий `infra/native_runtime.py` включён в дистрибутив и работает без путей ноутбука разработчика. Подготовлен [Linux-профиль Ubuntu 24.04](LINUX-INSTALLER.md); установка на настоящей Ubuntu ещё требует приёмки.

1. Полный путь через реальный HTTPS на одном ноутбуке пройден: существующий аккаунт портала, свежий код, рабочий сервер, публичный мастер, приглашение в независимой сессии и приватные файлы. Физический второй ПК, чистый Windows и реальная перезагрузка остаются обязательными перед массовым выпуском.
2. Перенос прежней SQLite: резервная копия, импорт в отдельную PostgreSQL, сохранение ключей шифрования и сравнение количества объектов. При ошибке исходная установка должна оставаться доступной для отката.
3. Безопасное обновление службы: резервная копия, подготовка новой версии отдельно, переключение и откат. Уже зарегистрированная служба не перезаписывается повторным запуском установщика.
4. Завершение единого пути скачивания: выбор установщика рабочего сервера, понятное отображение назначенного адреса и подтверждённой публичной готовности. Обычный `Setup-OwnDesk.cmd` пока сохраняет прежний локальный запуск.
5. Linux: чистая Ubuntu 24.04 x86-64, полный мастер, доступ с другого ПК, Telegram, файлы, перезагрузка и восстановление.

Универсальный установщик EXE пока не готов. Текущий Windows-профиль остаётся предварительным до полной приёмки новой публичной установки.
