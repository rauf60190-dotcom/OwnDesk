# Установка OwnDesk на Ubuntu Server

Основная целевая система первого Linux-профиля — **Ubuntu Server 24.04 LTS, x86-64 (amd64)**. Ubuntu 26.04 LTS, Debian и ARM пока не входят в проверенную матрицу. Стандартная поддержка Ubuntu 24.04 заканчивается в мае 2029: [цикл Ubuntu](https://ubuntu.com/about/release-cycle). Docker официально поддерживает Ubuntu 24.04 и 26.04: [инструкция Docker](https://docs.docker.com/engine/install/ubuntu/).

## Состояние реализации

17 ноября 2026 на чистой Ubuntu 24.04 amd64 в Hyper-V проверен полный сценарий установки 0.4.33: штатный `Setup-OwnDesk.sh`, собственная PostgreSQL, привязка к порталу, выделенный HTTPS-адрес, одноразовая настройка владельца, приглашение и повторный вход сотрудника. Через реальные HTTPS-запросы проверены переписка с отдельным тестовым клиентом, приватные фото/видео, скрытые внутренние заметки, дополнение описания, передача L1 → L2 → L3 → разработчики и закрытие тикета. Итоги отчётов за сегодня, вчера, неделю и месяц согласованы с данными графика и сотрудников. После перезагрузки гостевой Ubuntu Docker и оба контейнера запустились автоматически, записи и вложения сохранились. Это проверка одной VM; отдельный физический сервер и второй физический клиент не проверялись.

В 0.4.32 исправлено исключение `frontend/dist` из контекста Docker. В 0.4.33 при сборке удаляется ненужная файловая capability у Caddy: она мешала запуску с `cap_drop: ALL`. Приложение остаётся под UID 10001, с файловой системой только для чтения и no-new-privileges; опубликованных портов PostgreSQL нет. 19 сценариев логики установщика ранее проверены отдельно с имитацией Docker и сети.

В 0.4.34 добавлены [команды резервных копий Linux](LINUX-BACKUPS.md): создание, проверка SHA-256, изолированное восстановление и ежедневный systemd timer. На настоящей PostgreSQL сверены 42 таблицы и файлы, ключи и ограниченная роль приложения. Windows-команда `native_backup.py backup` для Linux по-прежнему не предназначена. В 0.4.35 добавлено [служебное обновление Linux с откатом](LINUX-UPDATES.md), сохранением текущей базы и журналом прерывания. Изменение схемы и переключение восстановленного экземпляра в рабочий режим остаются отдельными этапами.

## Сценарий установки

1. Создайте аккаунт владельца на owndesk.work. В «Мои установки» получите код подключения. Сам код действует 15 минут, поэтому лучше получить его после подготовки сервера, непосредственно перед вводом в установщик.
2. Распакуйте полный дистрибутив на Ubuntu в постоянный каталог. Не устанавливайте поверх чужого проекта. Для команд ниже нужен sudo.
3. Запустите:

```bash
sudo bash Setup-OwnDesk.sh
```

До изменения системы скрипт проверяет действие и параметры командной строки. Для `--help` не нужны sudo и Docker. Скрипт проверяет дистрибутив и архитектуру, при необходимости устанавливает Docker Engine и Compose plugin из официального репозитория Docker и включает службу Docker. Существующий Docker не переустанавливается; если нет Compose plugin, скрипт остановится с инструкцией. Нужен актуальный Compose v2 с поддержкой `up --wait`.

Затем создаётся отдельный Compose-проект с постоянными томами, случайными реквизитами базы и закрытым каталогом настроек `.runtime/linux`. Скрипт собирает образ OwnDesk из файлов дистрибутива. Начальная сборка и загрузка образов требуют интернета и могут занять несколько минут. Когда установщик запросит код подключения, получите свежий код в кабинете и вставьте его в скрытый ввод.

Коннектор получает только свои реквизиты, создаёт выделенный адрес через портал и подтверждает защищённый сервер. На чистой базе предварительно создаётся одноразовый код владельца. После проверки состояния коннектора и реального ответа публичного API через HTTPS (без перенаправлений) скрипт печатает персональную ссылку мастера с кодом во фрагменте URL. Код не записывается в журналы серверных процессов. Откройте ссылку на своём компьютере, укажите организацию и создайте аккаунт владельца. Переход на готовый адрес можно делать из любого браузера; сотрудникам отправляйте приглашения после завершения настройки, а не первоначальную ссылку владельца.

Если сеть не пропускает QUIC, выберите HTTP/2:

```bash
sudo bash Setup-OwnDesk.sh install --protocol http2
```

## Запуск и остановка

```bash
sudo bash Setup-OwnDesk.sh status
sudo bash Setup-OwnDesk.sh stop
sudo bash Setup-OwnDesk.sh start
sudo bash Setup-OwnDesk.sh setup-link
```

При `start` установщик ожидает публичной готовности до трёх минут. `status`, `stop` и `setup-link` не устанавливают Python/Docker и не включают службу Docker. Если установка ещё не создана, команды управления завершаются с подсказкой сначала выполнить `install`.

Docker запускается через systemd, контейнеры имеют политику перезапуска `unless-stopped`. Отдельная служба OwnDesk systemd в этом профиле не создаётся. Установка не публикует входящие порты хоста: Caddy и API слушают loopback внутри контейнера, внешний доступ идёт через исходящий Cloudflare Tunnel.

PostgreSQL находится в отдельном контейнере. У приложения свой пользователь БД без superuser/createdb/createrole; административный пароль не передаётся рабочему приложению. Вложения и ключи хранятся в закрытом томе организации. Рабочий процесс запускается непривилегированным пользователем с файловой системой образа только для чтения. Учётная запись и документы организации не хранятся на центральном портале.

## Обновления и сохранность данных

Сохраняйте `.runtime/linux/installation.json`, `.runtime/linux/compose.env` и оба постоянных тома Compose. Пароли PostgreSQL не меняются при повторном запуске скрипта. Если пропала информация установки, сначала восстановите её из копии; скрипт не должен подменять старые реквизиты новыми.

Не удаляйте тома и не выполняйте `docker compose down --volumes` как способ исправления ошибки. Перед обновлением сохраняйте дамп PostgreSQL, закрытый том с ключами и файлами и информацию Compose-проекта. Универсальный перенос существующей Windows SQLite в Linux ещё не встроен в этот скрипт; подготовка чистой Linux-установки не является миграцией старой базы.

Перед публичным использованием Linux-профиля нужна приёмка на чистой Ubuntu 24.04: установка, мастер с другого компьютера, приглашение, фото/видео, настоящий Telegram-бот, перезапуск хоста и восстановление из резервной копии.

## Контрольный список приёмки на чистой Ubuntu

1. Проверить `bash -n Setup-OwnDesk.sh` и справку без sudo. Ошибочное действие или протокол должны завершаться до установки пакетов.
2. Выполнить установку свежего архива на Ubuntu Server 24.04 amd64. Проверить здоровые контейнеры, отсутствие опубликованных портов, пользователя `desk`, read-only образ и закрытые тома.
3. Открыть мастер на другом компьютере, создать владельца и пригласить сотрудника. Проверить отдельную сессию сотрудника и отсутствие административных прав.
4. Создать тестовые обращения, отправить длинное сообщение, JPEG и MP4; проверить просмотр и доступ к файлам только из своей организации.
5. Выполнить `stop`, убедиться в остановке контейнеров; затем `start`. Проверить прежний вход, сообщения и файлы, актуальный heartbeat и коннектор. Повторный `install` должен сохранять пароли и данные.
6. Сохранить дамп PostgreSQL, закрытый том и `.runtime/linux`; восстановить в отдельном тестовом окружении с проверкой записей и файлов.
7. После сохранения открытых приложений проверить настоящую перезагрузку тестового Linux-хоста и повторный вход с другого компьютера.

На текущем Windows-ноутбуке WSL-дистрибутив и Docker отсутствуют. Установка Linux, контейнерные проверки этого списка и перезагрузка хоста не проводились.
