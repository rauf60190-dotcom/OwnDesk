# Постоянные службы Windows

Портал владельцев и сервер организации запускаются раздельно. Вход в Windows и открытый терминал для служб не нужны. Ноутбук должен быть включён, подключён к интернету и не находиться в спящем режиме. Автозапуск не заменяет выделенный сервер.

| Компонент | Служба | Учётная запись ОС | Программа | Закрытые данные |
|---|---|---|---|---|
| Центральный портал | OwnDeskPortal | NetworkService | `C:\Program Files\OwnDesk\Portal` | `C:\ProgramData\OwnDesk\Portal` |
| Организация | OwnDeskServer | LocalService | `C:\Program Files\OwnDesk\Server` | `C:\ProgramData\OwnDesk\Server` |

Права устанавливаются по SID, независимо от языка Windows. Каждая служба читает свою программу, изменяет только свои данные и не читает закрытый каталог другой службы. Общий каталог продукта доступен обеим службам только для чтения. Администраторы Windows и SYSTEM сохраняют полный доступ. Это разделение ОС; компрометация администратора самого компьютера выходит за его границы.

PostgreSQL, API и Caddy слушают только loopback. Внешний HTTPS обслуживается туннелями Cloudflare. Главный токен управления Cloudflare, OAuth-реквизиты и корневой токен туннеля находятся только у портала. Организация получает собственные реквизиты подключения.

## Управление

В PowerShell от имени администратора:

```powershell
Get-Service OwnDeskPortal, OwnDeskServer
Restart-Service OwnDeskServer
Restart-Service OwnDeskPortal
```

Для подробных журналов используются `service-logs`, `api.log`, `postgres.log`, `caddy.log` внутри соответствующего закрытого каталога данных. При переносе базы дополнительный журнал — `initial-restore.log`. Не публикуйте эти каталоги и файлы с секретами.

Обе службы используют отложенный автоматический старт и восстановление через 30 секунд после аварийного завершения. Корректная остановка сначала завершает приложение и дочерние процессы, затем останавливает PostgreSQL. Остановка вручную не считается аварией.

Для регулярных копий текущих данных используйте [онлайн-копирование служб](NATIVE-BACKUPS.md). Копии первоначальной миграции не заменяют свежую резервную копию.

Для совместимых служебных выпусков доступен предварительный [обновлятор с возвратом программы](WINDOWS-UPDATES.md). Изменения схемы и рабочего приложения он отклоняет.

## Перенос прежней установки

Перед последней резервной копией вход роли приложения в старую БД временно запрещается, существующие соединения закрываются. Сохраняются логические дампы, исходные ключи, конфигурация и приватные файлы. Резервная копия миграции доступна только администраторам и SYSTEM в `C:\ProgramData\OwnDesk\MigrationBackups`.

Новый кластер создаётся под своей служебной учётной записью; старый каталог PostgreSQL не копируется поверх работающей базы. `initial_restore` разрешает импорт только в пустую базу, проверяет SHA-256 архива и количество строк каждой таблицы. Восстановление, проверки и отметка об успешном импорте фиксируются одной транзакцией. После успешного импорта повторный запуск не перезаписывает базу и не сравнивает изменившиеся рабочие данные с прежним снимком.

До публикации проверяются локальные API и интерфейс. После фиксации переключения автоматический возврат к прежней базе запрещён: на новом сервере уже могли появиться записи пользователей. В этом случае восстанавливают новую службу, а перенос новых записей или восстановление из копии выполняют отдельной процедурой.

## Приёмка

Постоянные службы портала и Qwerty запущены и проверены после отдельной остановки и повторного запуска каждой службы. Подтверждены режим Auto с DelayedAutoStart, сохранность ключей, конфигурации, количества рабочих записей и приватных файлов, публичный интерфейс и API, отказ неавторизованному запросу, начало Google OAuth, актуальный коннектор и heartbeat обработчика задач. Исходные учётные записи и адреса сохранены.

На этом ноутбуке отдельно проверены настоящий запуск портала под NetworkService с PostgreSQL и Caddy, остановка и повторный запуск. Два настоящих служебных процесса подтвердили отказ в чтении чужого закрытого каталога и записи в код. Временные службы удалены, публичный туннель теста не создавался.

Отдельная проверка PostgreSQL подтвердила импорт, отказ при неверной контрольной сумме, полный откат при несовпадении строк, повтор после такого отказа и сохранение новых записей после последующих запусков. Транзакционность опирается на [режим psql `--single-transaction` с `ON_ERROR_STOP`](https://www.postgresql.org/docs/17/app-psql.html).

Реальная перезагрузка компьютера и установка на чистом Windows остаются отдельными проверками. Перезагрузка не выполняется автоматически, чтобы не закрыть приложения пользователя.
