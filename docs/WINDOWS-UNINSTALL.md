# Удаление службы организации с сохранением данных

Статус: подготовлено в исходниках следующего кандидата. Опубликованный установщик0.4.43 ещё не содержит этой вкладки. Это не устранение SmartScreen и не подтверждение получения подписи.

## Через мастер

1. Откройте актуальный мастер OwnDesk с правами администратора и вкладку «Удаление службы».
2. Нажмите «Проверить службу организации». Проверьте имя OwnDeskServer, версию и каталог данных.
3. Введите `OwnDeskServer` и нажмите «Удалить службу, сохранив данные». Подтвердите отключение сайта организации.
4. Дождитесь результата и сохраните путь журнала операции. Для работающей службы сначала создаётся и проверяется резервная копия; при ошибке копии остановки и удаления регистрации не происходит.

Если служба уже остановлена, автоматического запуска ради копирования не будет. Свежая копия в таком случае не создаётся. Сохраните ранее завершённую копию и защитите оставшийся каталог данных. Повторная проверка после удаления сообщает, что служба не зарегистрирована; файлы не очищаются.

## Что изменяется

Удаляется только регистрация проверенной службы OwnDeskServer в Windows. Её процессы штатно останавливаются, автозапуск этой службы прекращается, организация с данного компьютера становится недоступна. Центральная OwnDeskPortal этим мастером не удаляется. Другие службы и посторонние процессы не останавливаются.

Программа и XML службы остаются в Program Files. База PostgreSQL, приватные вложения, настройки, ключи, mail-settings и коннектор остаются в ProgramData. Каталоги резервных копий и журналы тоже сохраняются. Эта операция не удаляет аккаунт портала, организацию и привязку в Cloudflare/OwnDesk. Для прекращения привязки владелец отдельно использует кабинет портала; не отзывайте её, если планируете вернуть прежний сервер.

Остаточные данные по-прежнему содержат секреты и обращения: сохранение файлов не делает их публичными. Они остаются в защищённых каталогах с прежними ACL.

## Проверки перед удалением

Сверяются фактическая учётная запись службы, зарегистрированный путь WinSW, точный SHA закреплённого WinSW, XML, версия и хеши обязательных закрытых настроек. После предварительной проверки изменение установки требует новой проверки. Junction/symlink и неподдерживаемая конфигурация отклоняются. Удаление использует тот же lock, что обновление, и отклоняется при незавершённом переключении или восстановлении.

Для работающей службы создаётся native-резервная копия, затем служба останавливается и повторно проверяется. После удаления регистрации проверяется её отсутствие и сохранность ключей/конфигурации, host и XML. При отказе удаления и сохранившейся неизменённой регистрации предпринимается возврат прежнего рабочего состояния. Подтверждение восстановления пишется в журнал; неподтверждённый исход не отображается как успех. Резервная база не восстанавливается поверх текущих данных.

## Журнал и возврат регистрации

Журнал хранится в закрытом `%ProgramData%\OwnDesk\ServiceRemovals\OwnDeskServer\<идентификатор>\removal.json`. Рядом сохранён XML перед удалением. Для работавшей службы путь новой резервной копии указан в журнале; при остановленной значение backup_directory пустое.

Для возврата неизменённого сервера администратор сначала сверяет сохранившийся host/XML и пути с журналом. Затем запускает команды для сохранённого host:

```powershell
& 'C:\Program Files\OwnDesk\Server\OwnDeskService.exe' install
& 'C:\Program Files\OwnDesk\Server\OwnDeskService.exe' start
```

Это повторная регистрация прежнего кода с прежней базой, а не запуск установки новой организации. Команды применимы только к сохранённой проверенной установке с соответствующим XML; при изменении программы/ключей нужна отдельная процедура восстановления. Автоматическая повторная регистрация после успешного удаления не выполняется.

## Приёмка и границы

Пройдены101автоматическая проверка удаления/установки/обновления/восстановления, включая отказ копии, устаревшую проверку, смену host/XML/ключей/состояния, незавершённое обновление, сохранение файлов и отказ SCM. Проверка виджетов подтвердила блокировку кнопки до проверки и точного подтверждения, отмену и отключение действий в preview.

В настоящей Windows зарегистрирована отдельная синтетическая служба OwnDeskUninstallAcceptance044 в состоянии Stopped/Manual. Она не запускалась. Проверенное удаление регистрации сохранило8контрольных файлов программы/данных и убрало только временную службу. Рабочие OwnDeskServer/OwnDeskPortal не изменялись. Полный сценарий с настоящей работающей PostgreSQL в этой приёмке удаления не выполнялся: ветка running/backup проверена автоматическими тестами с имитацией, а native backup отдельно проверялся ранее.

Автоматической очистки файлов программы или данных здесь нет. Если нужна окончательная очистка, сначала сохраните и проверьте копию, подтвердите отсутствие службы и использование каталогов другими установками. Удалять весь общий каталог OwnDesk нельзя: в нём могут находиться портал, другие версии и резервные копии. Эта операция требует отдельного точного выбора каталогов; мастером автоматически она не выполняется.
