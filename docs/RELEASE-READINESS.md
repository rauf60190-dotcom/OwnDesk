## Этап 1. Доверенная подпись Windows

Подготовлены исходный репозиторий, политика подписания, CI и материалы заявки SignPath. Статус 2FA владельца GitHub не подтверждён; SignPath не подключён, заявка не отправлена. Нужны подтверждение MFA и решение фонда. Одобрение нельзя гарантировать.

После доступа к подписанию: подписать собственные компоненты в правильном порядке, пересобрать payload после изменения его байтов, подписать окончательный EXE, проверить цепочку сертификата, временную метку и контрольные суммы. Сторонним бинарникам не подменять издателя OwnDesk. [План доверенной установки](WINDOWS-INSTALLER-ACCEPTANCE.md) и [Code signing policy](CODE-SIGNING-POLICY.md).

## Этап 2. Полная приёмка окончательного установщика

На чистой Windows проверить реальный скачанный файл с сохранённой интернет-меткой и включённой защитой: отмену до подготовки, UAC, окно мастера, новую организацию, службу, повторный запуск, перезагрузку, обновление, возврат программы и удаление службы с сохранением данных. Изменять рабочую организацию для этой проверки не требуется.

На Ubuntu 24.04 проверить точный будущий пакет: установку, запуск после перезагрузки и восстановление из резервной копии в изоляции. Другие дистрибутивы и ARM не включать в список проверенных без отдельной приёмки.

Результат этапа — протокол с версией, хешами и фактическими результатами. Код программы пока не нужно переписывать: исправляются только обнаруженные дефекты.

## Этап 3. Закрытый тест с новым пользователем

Другой компьютер и сеть: регистрация по email, подтверждение адреса, повторный вход, полное восстановление пароля по настоящему письму, установка организации и переход по приглашению сотрудника. Затем проверить переписку, приватные фото/видео, ограничения ролей, блокировку сотрудника, эскалации и отчёты. Использовать синтетические обращения и отдельную организацию.

Новый Google-аккаунт проверяется отдельно, когда он будет доступен. До этого не объявлять массовую Google-регистрацию проверенной. Статус публикации Google OAuth для внешних пользователей тоже требует отдельного подтверждения. Если первый тест проводится только по email, это нужно явно сообщить участникам.

## Этап 4. Условия постоянной работы

Портал пока работает на ноутбуке: выключение, сон и потеря интернета влияют на доступность. Для круглосуточного сервиса выбрать постоянный хостинг портала, перенести его с резервной копией и проверить возврат. Серверы организаций и их данные при этом остаются у их владельцев.

Проверить расписание резервного копирования, восстановление в отдельное хранилище, уведомления о сбоях и процедуру обновлений. В кандидат добавлены [стартовые рекомендации по компьютеру](HARDWARE-REQUIREMENTS.md): 2 vCPU, 4 ГБ RAM и 20 ГБ свободного места. Они показываются в кабинете перед скачиванием и в мастере Windows; локальная проверка ресурсов не отправляет характеристики в сеть и не блокирует установку. Измеренный минимум ещё требует нагрузочного тестирования и публикации его результатов.

## Этап 5. Публикация

Назначить номер нового выпуска, собрать окончательные байты и повторить необходимые проверки для них. Опубликовать понятную инструкцию, сведения об издателе/подписи, контрольные суммы, ограничения и ссылку на политики. Проверить настоящее скачивание через кабинет. Затем открыть доступ более широкой аудитории и собирать замечания.

Отдельная панель владельца платформы для блокировки аккаунтов, другие Linux-дистрибутивы и настольное клиентское приложение — будущие решения по продукту; они не являются автоматически обязательными для первого закрытого теста.
