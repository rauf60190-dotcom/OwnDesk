# Исчерпание соединений PostgreSQL и исправление

Итог: обе рабочие службы исправлены и доступны. Общий установщик41 опубликован, скачан через настоящий кабинет и сверён с принятым ZIP по SHA-256 и размеру. Протоколы release041-published.json и release041-download-verified.json. Публикация не перезапускала службы; предыдущий39 сохранён отдельно. Ниже описаны причины и этапы подготовки, включая промежуточное ожидание подтверждения Windows.

18 ноября2026 рабочее пространство Qwerty стало недоступно: Cloudflare530, локальная readiness503. Служба продолжала работать, но PostgreSQL отклонял соединения: `too many clients already` и `remaining connection slots are reserved`. У процесса API были97 TCP-соединений с PostgreSQL при лимите100. Последующий снимок после освобождения части соединений всё ещё показал24 idle подключения, самые старые старше полутора часов.

Причина подтверждена воспроизведением: в ASGI использовался `CONN_MAX_AGE=60`, и соединения завершённых запросов оставались открытыми. Изолированный тест100 запросов с параллелизмом4 и PostgreSQL max_connections40 провалился на прежней настройке и прошёл при0. Новая настройка закрывает соединения по завершении запроса. Лимит PostgreSQL не увеличивался. [Django рекомендует отключать persistent connections в ASGI](https://docs.djangoproject.com/en/5.2/topics/async/).

Добавлена PostgreSQL-регрессия `tests/test_asgi_connections.py`: настоящий ASGI application,100 HTTP-запросов, проверка отсутствия накопившихся соединений через pg_stat_activity. На Windows327 остальных тестов прошли,3 Linux-зависимые пропущены,3 PostgreSQL исключены из этого запуска. Новая PostgreSQL-регрессия отдельно воспроизведена и исправлена на Ubuntu в контейнерах без публичных портов; контейнер базы и сеть удалены.

## Восстановление работающих служб

Сначала восстановлена доступность Qwerty перезапуском. Затем применено отдельное аварийное исправление одного файла к установленным службам, без общего обновления backend или изменения схемы. Обычные ограничения maintenance/updater не отключались. Guard сравнивает точные старые и новые байты settings с проверенным baseline и разрешает только conn_max_age60→0 и два поясняющих комментария. Перед остановкой создаётся проверенная онлайн-копия данных и отдельная копия прежнего файла программы; при ошибке запуск возвращает прежний файл с текущей базой. Исходная база не восстанавливается из старой копии.

Служба Qwerty остаётся версией26 с зарегистрированным исправлением конфигурации, портал —40 с тем же исправлением. Они не выдаются за полное обновление до41. Протоколы: asgi041-server-hotfix.json и asgi041-portal-hotfix.json. После применения проверяется публичная readiness и50 запросов к каждому серверу; до и после замеряется число подключений роли приложения. Пароли, пользователи, переписка и вложения не изменяются.

Общий установочный выпуск41 включает правильную настройку по умолчанию. Его публикация требует отдельной приёмки точного ZIP на Windows/Linux. Старые протоколы39 и40 не заменяют эту приёмку.

Обе рабочие службы исправлены и проверены: по50запросов, число подключений до0 и после0, публичная готовностьok. В браузере загрузилась авторизованная очередь Qwerty.
