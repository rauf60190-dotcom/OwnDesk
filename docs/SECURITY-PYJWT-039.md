# Обновление PyJWT в 0.4.39

Портал обновлён и проверен: `security039-deployed.json`, active_pyjwt2.15.1; настоящий Google-вход владельца на новой программе успешен. До переключения изолированная NetworkService прошла38→39, намеренный отказ с возвратом прежней программы/библиотеки и сохранением новой записи, успешное обновление и перезапуск. Windows fresh LocalService и Linux-образ из точного кандидата также проверены. Итоговые проверки:327 наWindows,62+34 наLinux и2PostgreSQL. Резервная копия рабочего переключения: `C:\ProgramData\OwnDesk\Backups\OwnDeskPortal-before-25eb43917fd64c8891ae889b972de849`. Исходный ZIP39 не пересобирался после этих правок документации.

При подготовке закрытого теста pip-audit сообщил22 записи о проблемах PyJWT2.10.1. В списке есть повторяющиеся идентификаторы и спорное сообщение; число записей не означает22 разных способов атаковать OwnDesk. В исходниках Google-вход использует фиксированный HTTPS-адрес ключей Google, единственный разрешённый алгоритмRS256, проверку audience/issuer/nonce/verified email. Сценарии смешивания HMAC/RSA и произвольного адреса JWKS к этому коду напрямую не относятся. При этом библиотека участвует в разборе токена до проверки подписи, поэтому обновление требуется независимо от ограничений алгоритма.

Закреплён PyJWT2.15.1. Официальные источники: [changelog](https://pyjwt.readthedocs.io/en/stable/changelog.html), [выпуск PyPI](https://pypi.org/project/PyJWT/2.15.1/). Повторный аудит requirements не сообщил известных уязвимостей. Это результат проверки базы advisories, не гарантия отсутствия всех проблем.

Добавлены проверки настоящего пути JWT/JWK без внешних запросов: корректный подписанный Google ID token, мусор в подписи, неверные типы exp/iat и глубоко вложенный payload. После обновления зависимости пройдено313 тестов на Windows; затем добавлены отдельные проверки режима обновления. Окончательные протоколы и число тестов записываются отдельно после сборки.

## Обновление существующего центрального портала

Стандартный maintenance-режим и `--frontend-only` продолжают отклонять смену зависимостей. Для проверенного перехода добавлен явный `--refresh-pyjwt`, только для portal check/apply и отдельно от `--frontend-only`. Он разрешает ровно замену строки PyJWT2.10.1 на2.15.1; остальные байты requirements, backend, frontend, runtime и закреплённые компоненты должны совпасть. Установленный PyJWT перед подготовкой также должен быть2.10.1. Все другие Python-пакеты в отдельном окружении сохраняют прежние версии; подготовленный состав сверяется до остановки службы.

Режим не включает миграции данных и не разрешает общий произвольный переход между версиями backend. Рабочая база остаётся текущей при возврате программы. Применению предшествуют изолированная проверка успешного обновления и намеренного отказа, свежая резервная копия и проверка публичной готовности. До успешного протокола обновления нельзя считать рабочий портал исправленным только по изменению requirements в исходниках.

Для новой организации используется обычный установщик с новым pin. Существующий сервер организации не получает незаметного обновления через этот флаг: для него нужен отдельный проверенный переход. Пока он остаётся на26; Google-вход на нём не настроен, но библиотека всё равно должна учитываться в дальнейшем плане обновлений.
