# Рабочий сервер OwnDesk на Windows

Рабочий установщик `Setup-OwnDesk-Server.cmd` подготавливает Python, PostgreSQL и службу Windows для новой организации. Добавлена [автоматическая подготовка подписанного Python](PYTHON-BOOTSTRAP.md); настоящая служба под LocalService проверена с новым интерпретатором. В 0.4.25 пройден [новый публичный сценарий на одном ноутбуке](PUBLIC-INSTALLATION-ACCEPTANCE.md). Чистый Windows, физический второй ПК и перезагрузка ОС ещё требуют приёмки; установщик остаётся предварительным.

## Что потребуется

- Windows x86-64 с PowerShell 5.1 / .NET и интернет. Установщик сам скачивает подписанный Python 3.14.10 и проверяет его перед запуском. Предварительная ручная установка Python не требуется.
- Права администратора для установки службы и закрытых каталогов. Windows покажет запрос UAC.
- Аккаунт на owndesk.work. Свежий код подключения потребуется после загрузки компонентов.
- Свободные локальные порты 5173, 8000 и 55486. Новая служба рассчитана на одну организацию на компьютере. Порты не открываются во внешнюю сеть.

## Как установить новую организацию

1. Распакуйте чистый дистрибутив полностью. Откройте `Setup-OwnDesk-Server.cmd` и подтвердите запрос Windows.
2. Дождитесь автоматической загрузки и проверки Python. Затем в основном тёмно-синем окне нажмите «Установить и запустить». Подготавливаются отдельное окружение сервера, зависимости и проверенные бинарные компоненты. Первый запуск может занять несколько минут.
3. Когда появится запрос кода, откройте owndesk.work → «Мои установки», получите свежий код и вставьте его в скрытое поле. Код не передаётся в аргументах процесса и не записывается в журнал установщика.
4. Установщик назначит HTTPS-адрес организации, зарегистрирует службу `OwnDeskServer` и дождётся активации коннектора. Затем откроет персональную ссылку браузерного мастера. Укажите организацию и создайте владельца.
5. После установки окно можно закрыть. Автоматический запуск службы настроен с задержкой после загрузки Windows. Компьютер должен оставаться включённым и иметь интернет; сон/выключение делают организацию недоступной.
6. Сотрудникам отправляйте приглашения из настроек организации. Первоначальную ссылку мастера владельца передавать сотрудникам не нужно.

## Программа и данные

- `%ProgramFiles%\OwnDesk\Server` — защищённый код, отдельный Python, окружение и проверенные компоненты. LocalService имеет доступ только на чтение и выполнение.
- `%ProgramFiles%\OwnDesk\Bootstrap` — закреплённый Python для запуска окна мастера с проверкой сохранённых файлов.
- `%ProgramData%\OwnDesk\Server` — PostgreSQL, закрытые вложения, ключи, профиль подключения и журналы. Доступ ограничен администраторами, SYSTEM и LocalService.
- Служба работает под `NT AUTHORITY\LocalService`; установщик проверяет фактическую учётную запись после регистрации. Если проверка не пройдена, служба удаляется до запуска, данные сохраняются.
- PostgreSQL слушает только loopback. У приложения собственная роль базы; ключ Cloudflare всего домена ему не передаётся.

Запрос остановки службы передаётся основному процессу через закрытый каталог. Он останавливает API, коннектор и Caddy, затем корректно завершает PostgreSQL. WinSW оставляет до 60 секунд на завершение, затем применяет принудительную остановку.

## Управление

Откройте «Службы» Windows (`services.msc`) и найдите **OwnDesk Server**. Можно запустить или остановить службу. Журналы находятся в каталоге данных; окно установщика содержит кнопку «Журналы». «Открыть организацию» проверяет свежий статус коннектора перед открытием браузера.

Команды из PowerShell администратора:

```powershell
& "$env:ProgramFiles\OwnDesk\Server\OwnDeskService.exe" status
& "$env:ProgramFiles\OwnDesk\Server\OwnDeskService.exe" stopwait
& "$env:ProgramFiles\OwnDesk\Server\OwnDeskService.exe" start
```

При занятом порте установщик останавливается до копирования и привязки. Он не завершает чужие процессы. При прерывании скачивания недописанный файл не используется; перед распаковкой проверяются точный размер и зафиксированный SHA-256, перед повторным использованием компонентов — хеши извлечённых файлов. При потере ответа портала сохраняется идентичность подключения для повтора: оставьте код пустым. Если код истёк до привязки, введите новый. Отмена диалога сохраняет зависимости и завершает подготовку без запуска службы.

«Открыть организацию» проверяет совпадение адреса с идентификатором привязки, свежий статус коннектора и настоящий ответ HTTPS-проверки без перехода на другой адрес. Один старый статус active не считается подтверждением работающего сервера.

Если служба уже зарегистрирована, повторная установка отказывается перезаписывать её. Запуск и диагностика выполняются отдельно. Обновление с резервной копией и откатом остаётся следующим блоком.

## Ограничения и приёмка

В исходниках следующего кандидата подготовлено [удаление службы организации с сохранением данных](WINDOWS-UNINSTALL.md). В опубликованном0.4.43 этой вкладки ещё нет. Это не подтверждение прохождения SmartScreen или получения подписи.

Автоматический перенос прежней SQLite-базы не включён. При обнаружении локальной базы в исходном дистрибутиве установка новой организации останавливается. Не удаляйте старую установку: перенос требует отдельного резервного копирования и проверки данных. `Setup-OwnDesk.cmd` продолжает запускать прежний локальный мастер; рабочий сервер устанавливается отдельной командой.

На новом Python пройдены 133 серверные проверки: 131 на SQLite и две проверки PostgreSQL. Проверены настоящая загрузка и распаковка компонентов, повторная проверка хешей, фильтрация ZIP-путей, сценарии повреждённого файла и отказ при занятом порте. Настоящая временная служба запустила PostgreSQL, API и Caddy из Program Files на портах 15586, 18000 и 15173; интерфейс и проверка API отвечали. Фактический StartName был LocalService, режим запуска — Auto. Проверены `stopwait`, повторный запуск с той же базой и автоматическое восстановление после намеренного сбоя. После приёмки временная служба удалена. Рабочая организация в этом тесте не использовалась; на ней отдельно подтверждены сохранность владельца и работа коннектора.

Во время приёмки исправлены копирование шаблонов venv, права временных каталогов после переноса и путь Program Files с пробелами. Каталоги кода получают наследуемое чтение/выполнение для LocalService, без доступа на изменение; каталог данных имеет отдельный точный список разрешений.

Пройден новый публичный мастер, приглашение в независимой сессии и приватные фото/видео именно новой служебной установки. Остаются чистый Windows, физический второй ПК, реальная перезагрузка ОС, Telegram, SMTP и восстановление из резервной копии новой установки. Автоматический режим запуска проверен по конфигурации Windows, а не реальной перезагрузкой. Пока эти проверки не завершены, установщик не обозначается готовым для массовой установки.

Источники компонентов: [PostgreSQL для Windows](https://www.postgresql.org/download/windows/), [бинарные сборки EDB](https://www.enterprisedb.com/download-postgresql-binaries), [Caddy 2.10.2](https://github.com/caddyserver/caddy/releases/tag/v2.10.2), [cloudflared 2026.10.7](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.7), [WinSW 2.12.0](https://github.com/winsw/winsw/releases/tag/v2.12.0). Настройки службы соответствуют [документации WinSW 2](https://github.com/winsw/winsw/blob/v2.12.0/doc/xmlConfigFile.md).
