# Изолированный Windows-прогон службы

`tools/ci_windows_service.py` предназначен только для одноразового Windows runner репозитория OwnDesk на GitHub. Он отказывается работать как обычная команда установки на компьютере пользователя. Исходники берутся из EXE, уже распакованного диагностическим режимом; коммит payload должен совпасть с текущим запуском CI.

Прогон подготавливает приложение штатным `prepare_application`, скачивает зависимости с проверкой закреплённых SHA-256, сверяет скопированные файлы и регистрирует отдельную настоящую службу под LocalService. У неё уникальное имя `OwnDeskCI…`, отдельные каталоги Program Files/ProgramData и порты 15586, 18000, 15173. Служба OwnDeskServer не используется.

Тестовый процесс запускает настоящие PostgreSQL, Django/ASGI и Caddy, применяет миграции и строгую проверку настроек deployment. Проверяются HTTP API и интерфейс, автоматический тип запуска, остановка и повторный старт с сохранением синтетической организации, затем автоматическое восстановление после намеренного сбоя процесса. В завершение удаляется только созданная регистрация службы после сверки её пути. Файлы сохраняются до уничтожения одноразового runner.

Для прогона создаётся локальная синтетическая запись подключения. Запросов к порталу, создания DNS, туннеля Cloudflare, отправки сообщений и писем нет. Вложенный probe не запускает публичный коннектор. Из сетевых операций нужны только загрузки компонентов и Python-пакетов.

Отчёт `service-acceptance.json` входит в CI-артефакт; подробные журналы и конфигурация с временными секретами не загружаются. В отчёте явно указано, что GUI, UAC, реальная перезагрузка ОС и публичное подключение не проверялись. При ошибке всего workflow его артефакты не являются принятым выпуском.

Этот тест подтверждает работу серверной части кандидата в изоляции. Он не заменяет [полный протокол установки](WINDOWS-INSTALLER-ACCEPTANCE.md), подпись или проверку скачанного EXE с защитными политиками Windows.

## Совместимость PowerShell

Первый прогон выявил конфликт унаследованного `PSModulePath`: при цепочке PowerShell 7 → Python/EXE → Windows PowerShell 5.1 стандартный модуль Security мог разрешаться в несовместимую версию. Дочерние процессы Windows PowerShell теперь получают окружение без этой переменной и строят свои стандартные пути самостоятельно. Это применяется к подготовке каталогов, проверкам служб и запуску bootstrap из EXE/CMD; окружение родителя не изменяется. Права доступа и политики защиты остаются прежними. Основание: [документация Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_psmodulepath).
