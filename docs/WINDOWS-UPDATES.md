# Обновление служб Windows с возвратом к прежней программе

`infra/windows_update.py` — предварительный обновлятор для служебных сборок OwnDesk на Windows. Он проверяет архив, подготавливает отдельный каталог программы и создаёт свежую резервную копию до остановки службы. При неудачном запуске возвращает прежнюю программу с **текущей рабочей базой**, сохраняя записи, принятые после переключения.

## Какие обновления разрешены

Первый вариант принимает только более новую сборку с теми же файлами `backend`, `frontend/dist`, основными модулями запуска/восстановления и теми же закреплёнными PostgreSQL, Python, Caddy, cloudflared и WinSW. Python-пакеты нового окружения устанавливаются в точных версиях из существующего окружения; расхождение блокирует переключение. Серверный код, схема, интерфейс и поведение рабочего runtime в этом режиме не меняются; обновляться могут вспомогательные инструменты и документация.

Обновления с новой схемой, изменением серверного кода или зависимостей требуют отдельного механизма совместимости и восстановления. Обновлятор отклоняет их до остановки службы.

## Отдельный режим интерфейса портала, начиная с 0.4.36

CLI поддерживает явный `--frontend-only` для `check` и `apply` службы `OwnDeskPortal`. Он разрешает отличаться только ранее запрещённой части `frontend/dist`: весь `backend`, включая миграции и requirements, закреплённые зависимости и основные runtime-файлы по-прежнему должны совпадать. Поле в архиве не может самостоятельно включить этот режим. Служба организации и графическое окно по умолчанию остаются в служебном режиме.

Используются прежние проверка ZIP/SHA-256, отдельный подготовленный каталог, точные версии пакетов Python, проверка файлов после подготовки, свежая резервная копия, журнал переключения и автоматический возврат программы с текущей базой. Тип перехода записывается в `update_kind`. Восстановление по журналу не требует повторять флаг: `recover` работает с сохранённым переходом.

Перед применением новой страницы проверить её в браузере, отсутствие изменений API-контракта и работу после возврата на прежний интерфейс. Это не режим произвольного обновления приложения и не разрешение выполнять новые миграции. Текущая приёмка и публикация страницы фиксируются в рабочем протоколе отдельно от дистрибутива.

```powershell
python infra/windows_update.py check --service OwnDeskPortal --archive C:\OwnDesk.zip --sha256 <доверенная_SHA256> --frontend-only
python infra/windows_update.py apply --service OwnDeskPortal --archive C:\OwnDesk.zip --sha256 <доверенная_SHA256> --frontend-only
```

## Обновление через окно установщика

Откройте `Setup-OwnDesk-Server.cmd` из нового распакованного дистрибутива и подтвердите стандартный запрос администратора Windows. Перейдите на вкладку **«Обновление и возврат»**:

1. Выберите «Организация» или «Портал владельцев». Обновляется только выбранная служба.
2. Выберите ZIP-архив OwnDesk и вставьте SHA-256 из кабинета портала. Сумма указана рядом с дистрибутивом.
3. Нажмите «Проверить архив». После успешного результата окно покажет установленную и предлагаемую версии и включит «Обновить службу». Изменение архива, суммы или службы сбрасывает подтверждённую проверку.
4. Нажмите «Обновить службу» и подтвердите показанное переключение. В журнале отображаются подготовка, резервная копия, остановка, запуск и возможный возврат. Пока операция выполняется, изменение полей и закрытие окна блокируются.
5. После завершения можно закрыть окно: служба работает самостоятельно.

Если операция была прервана, выберите нужную службу, вставьте идентификатор из журнала и нажмите **«Восстановить запуск»**. Архив и SHA-256 для этого действия не требуются. После неудачного автоматического возврата окно подставляет идентификатор из сообщения обновлятора. Это возврат программы с текущей базой, а не восстановление старых данных из резервной копии.

На вкладке «Установка организации» сохранена первоначальная установка с кодом подключения. Окно обновления не выполняет миграции, которые запрещены текущей политикой совместимости.

## Проверка и применение из PowerShell

Получите архив и SHA-256 из доверенного кабинета портала; контрольная сумма показывается рядом с дистрибутивом. Из распакованного каталога OwnDesk запустите PowerShell от имени администратора:

```powershell
$taskPython = "$env:ProgramFiles\OwnDesk\Server\runtime\venv\Scripts\python.exe"
$taskArchive = 'C:\Downloads\OwnDesk.zip'
$taskSha = '<SHA-256 из кабинета портала>'

& $taskPython .\infra\windows_update.py check --service OwnDeskServer `
  --archive $taskArchive --sha256 $taskSha

& $taskPython .\infra\windows_update.py apply --service OwnDeskServer `
  --archive $taskArchive --sha256 $taskSha
```

Для портала используйте `--service OwnDeskPortal` и Python из `C:\Program Files\OwnDesk\Portal\runtime\venv\Scripts\python.exe`. Службы обновляются последовательно, отдельными операциями. На этапе переключения выбранный сайт временно недоступен; подготовка нового окружения выполняется при работающей старой службе.

До распаковки проверяются SHA-256, структура и общий размер архива, опасные Windows-имена, ссылки, повторяющиеся имена и выход за пределы каталога. Архивы с приватной базой, ключами или рабочим `.runtime` не принимаются.

## Что происходит при переключении

1. Подтверждаются зарегистрированные путь службы и учётная запись: LocalService для организации, NetworkService для портала. Рабочая XML-конфигурация должна соответствовать обычной установке OwnDesk.
2. Программа подготавливается в отдельном защищённом каталоге `ServerReleases` или `PortalReleases`. Существующая программа не перезаписывается. Устанавливаются только двоичные Python-пакеты в прежних точных версиях; новая программа сверяется с архивом.
3. Создаётся [онлайн-копия базы, ключей и вложений](NATIVE-BACKUPS.md). При её ошибке служба продолжает работать, переключение не начинается.
4. Служба корректно останавливается через WinSW `stopwait`. Только после подтверждения остановки атомарно меняются путь Python, рабочий каталог и аргументы запуска/остановки. Учётная запись, автозапуск и исходный WinSW остаются прежними.
5. После запуска проверяются локальный API и состояние службы. Для обычных публичных служб дополнительно проверяются публичный HTTPS и актуальный коннектор организации.
6. При неудачной проверке служба останавливается, возвращается прежний XML и запускается старая программа. Рабочая база, вложения и ключи не заменяются резервной копией.

Исходный каталог со стабильным `OwnDeskService.exe` и прежними бинарными зависимостями сохраняется: профиль данных продолжает указывать на них. Удалять его после обновления нельзя. Старые каталоги выпусков также автоматически не удаляются.

## Незавершённое переключение

Журнал находится в `C:\ProgramData\OwnDesk\ServiceUpdates\<служба>\<идентификатор>\update.json`, копия перед обновлением — в `C:\ProgramData\OwnDesk\Backups`. Они закрыты для обеих служебных учётных записей и доступны администраторам/SYSTEM. Только один обновлятор может работать с выбранной службой.

Если контроллер завершился во время переключения или возврат не подтвердился, выполните:

```powershell
& $taskPython .\infra\windows_update.py recover --service OwnDeskServer `
  --transaction '<идентификатор из сообщения об ошибке или журнала>'
```

Команда возвращает прежнюю программу с текущей базой. Другая операция обновления блокируется, пока не завершён прежний переход. Если XML изменил другой администратор, автоматическое восстановление отказывается его перезаписывать. При выключении питания после намеренной остановки службы для завершения перехода может потребоваться `recover`; отдельный фоновый наблюдатель пока не устанавливается.

Не восстанавливайте старую базу поверх рабочей как обычный откат программы. Резервная копия нужна для отдельной аварийной процедуры, а не для потери записей, появившихся после её создания.

## Приёмка и ограничения

Проверки архива и переходов покрываются автоматическими тестами, включая отказ при изменении приложения, опасные пути, ошибку резервного копирования и посторонний XML. Отдельная приёмка пройдена на временной NetworkService с PostgreSQL и Caddy: намеренный отказ новой сборки после записи в БД, сохранность этой записи после возврата, успешное обновление и повторный запуск. Тестовая служба не использовала публичный туннель и рабочие реквизиты. Проверены автоматический возврат без потери принятой записи, успешный переход 0.4.28 → 0.4.29 и сохранность данных после повторного запуска. Временная служба удалена. Публичная проверка обычных служб покрыта имитацией HTTP, реальное обновление публичной установки в этой приёмке не выполнялось.

Работающие публичные службы не обновляются при выполнении тестовой приёмки. Реальная перезагрузка ОС, чистый Windows и обновление с миграциями остаются отдельными этапами. Управление доступно в окне установщика и через административный инструмент командной строки. В предпросмотре все операции со службами отключены.
