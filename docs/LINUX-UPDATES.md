# Обновления Linux

`OwnDesk-Update.sh` проверяет SHA-256 архива и совместимость служебной сборки. Изменение приложения, зависимостей, runtime, схемы и Compose требует отдельного механизма миграций и этим обновлятором не принимается.

Перед запуском распакуйте новый дистрибутив в отдельный каталог, принадлежащий root и недоступный для записи другим пользователям. Рабочую установку поверх него не распаковывайте. SHA-256 берите из доверенных метаданных загрузки портала, а не из самого полученного архива. При staging проверка суммы повторяется над закрытой копией ZIP; выход за границы путей, ссылки, дубликаты и приватные файлы отклоняются.

Перед переключением создаётся проверенная копия. Меняется только контейнер приложения, PostgreSQL и тома сохраняются. При ошибке возвращается прежний образ с текущей базой; старый дамп автоматически не восстанавливается.

Команды `check`, `apply`, `rollback`, `recover`, `status` выполняются через sudo. Для первого обновления запускайте скрипт из отдельно распакованного нового дистрибутива, передавая `--root` с каталогом существующей установки.

```sh
sudo bash OwnDesk-Update.sh check --root /opt/OwnDesk \
  --archive /path/OwnDesk.zip --sha256 SHA256_FROM_TRUSTED_PORTAL
sudo bash OwnDesk-Update.sh apply --root /opt/OwnDesk \
  --archive /path/OwnDesk.zip --sha256 SHA256_FROM_TRUSTED_PORTAL
sudo bash OwnDesk-Update.sh rollback --root /opt/OwnDesk
sudo bash OwnDesk-Update.sh recover --root /opt/OwnDesk
```

По умолчанию копии создаются в `/var/backups/owndesk`; другой закрытый каталог задаётся через `--backup-dir`. Существующая установка должна быть включена и исправна. На сервере нужны исходные Docker-образы для отката; не удаляйте их и закрытый каталог `.runtime/linux/updates`.

Обновлятор использует общую блокировку с установщиком и копированием. Перед переключением записывается журнал и включается служба восстановления при загрузке. Она использует отдельную сохранённую копию драйвера. При незавершённом переходе остальные команды обслуживания блокируются до `recover`.

Первый выпуск обновляет образ приложения, VERSION и настройки выбора образа; также устанавливает две команды обновлятора. Остальные файлы каталога установки не переустанавливаются. Код backend/frontend, весь серверный Python runtime (кроме самого обновлятора), зависимости, Dockerfile и Compose должны совпадать с установленными. Дополнительно сравниваются файлы собранного образа и фактически установленные версии Python-пакетов с прежним образом. Контейнер PostgreSQL и том вложений не заменяются. Это не механизм произвольного изменения кода или структуры базы и не ежедневная автоматическая загрузка новых версий.

`recover` обрабатывает незавершённый переход и возвращает прежний образ с текущей базой. Успешно зафиксированный переход при очистке оставшегося журнала не откатывается. `rollback` применим только к последнему зафиксированному обновлению и сначала создаёт свежую копию. При недоступности публичного API или отсутствии старого образа восстановление может потребовать повторного запуска `recover`; журнал не удаляется до подтверждения готовности.

На отдельной публичной Ubuntu-установке реально проверены переход 0.4.34 → 0.4.35, ручной откат, намеренный отказ после записи новых данных и автоматический возврат. После SIGKILL процесса обновления выполнена настоящая служба systemd с сохранённым драйвером. Изменения данных сохранились во всех трёх случаях; ID контейнера PostgreSQL остался прежним. После этого повторно проверены через HTTPS вход владельца и сотрудника, переписка, фото/видео, права и отчёты. 62 проверки Linux пройдены. Это API/контейнерная проверка на одной VM, не физическое отключение питания и не перезагрузка ОС во время перехода. Рабочие Windows-службы не обновлялись.
