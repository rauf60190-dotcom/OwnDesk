# Проверка новой публичной установки

17 ноября 2026 тот же публичный сценарий выполнен на чистой Ubuntu 24.04 amd64 в отдельной Hyper-V VM со штатным `Setup-OwnDesk.sh` версии 0.4.33. Дополнительно проверены клиентская переписка с приватными фото/видео, скрытые заметки, дополнение тикета, вся цепочка эскалации, отчёты и сохранность записей/вложений после автоматического запуска при реальной перезагрузке гостевой ОС. Холодный снимок восстановлен в отдельные закрытые тома и PostgreSQL, сверены 42 таблицы, файлы и ключи; восстановленное приложение не запускалось. Это API-проверки через настоящий HTTPS с независимыми сессиями, а не ручная визуальная проверка браузера и не второй физический компьютер. Подробности: [LINUX-INSTALLER.md](LINUX-INSTALLER.md).

Проверка выполнена 16 ноября 2026 года на текущем Windows-ноутбуке. Использованы новая пустая база PostgreSQL, отдельные каталоги программы и данных, отдельное имя службы LocalService и обычные рабочие порты OwnDesk. Установщик запускался через тот же `windows_service.install`, который использует окно мастера.

Подтверждено реальными HTTPS-запросами:

1. Существующий владелец получил код подключения через авторизованную сессию портала owndesk.work. Внешний вход Google в этом прогоне не повторялся.
2. Коннектор привязался к порталу, автоматически получил отдельный адрес `https://org-<id>.owndesk.work` и активировал маршрут после проверки готовности. Новый домен покупать не требуется.
3. На пустой базе открылся защищённый мастер. Неверный код отклонён; правильный код создал организацию и владельца. Повторная первоначальная настройка после создания организации запрещена.
4. Сессионные cookie имеют Secure / HttpOnly. Владелец получил доступ к рабочим разделам и отчётам и повторно вошёл по своим реквизитам.
5. Ссылка приглашения содержит публичный HTTPS-адрес организации. Сотрудник принял её в независимой HTTP-сессии, получил роль оператора и повторно вошёл. Повторное использование приглашения отклонено; оператору отказано в административном разделе подключения.
6. JPEG и MP4 загружены и получены владельцем без изменения содержимого. Гостю и сотруднику без доступа отказано в просмотре этих вложений; ответ владельцу помечен как приватный.
7. Отзыв подключения выполнен через публичный портал. Тестовые DNS-записи, туннели, временные службы, записи подключений и короткие тестовые сессии портала удалены. Аккаунты организации не копировались в базу центрального портала.
8. Исходная организация восстановлена автоматически с сохранением владельца и её прежней базы. Перед проверкой сделана резервная копия. Диагностические файлы и синтетические базы сохранены в закрытых тестовых каталогах.

В первом прогоне Cloudflare возвращал HTTP 403 / 1010 на стандартный User-Agent urllib. Поэтому окно установщика не признавало активный адрес готовым. Проверка теперь отправляет явный идентификатор OwnDesk и Accept: application/json; повторный сквозной прогон завершён успешно. Добавлена регрессионная проверка этого запроса.

Ограничения результата: все процессы и HTTP-клиенты находились на одном ноутбуке, хотя запросы шли через настоящий интернет-адрес и Cloudflare Tunnel. Физический второй компьютер, чистая Windows, перезагрузка ОС, SMTP и вход нового пользователя Google в этом прогоне не проверялись. Приглашение создавалось без отправки письма. Эти пункты остаются отдельными шагами приёмки.

Для повторного использования обычного установщика см. [Windows Server](WINDOWS-SERVER-INSTALLER.md). Проверка удаления соединений выполнялась по [API Cloudflare](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/connections/methods/delete/).
