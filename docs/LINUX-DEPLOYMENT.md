# Развёртывание организации на Linux

Основная целевая ОС — Ubuntu Server 24.04 LTS x86-64. Для установки через адрес OwnDesk без входящих портов подготовлен [новый Linux-установщик](LINUX-INSTALLER.md). Он использует общий нативный модуль и контейнеры; полная приёмка на Ubuntu ещё предстоит. Ниже сохранён альтернативный распределённый вариант с собственным доменом, Redis/Celery и S3.

Подготовьте Linux-сервер с Docker Engine и Compose v2. Направьте DNS-имя на сервер и откройте входящие TCP-порты 80 и 443. Если добавляете AAAA-запись, проверьте доступ по IPv6. Caddy получает и обновляет сертификат, а данные сертификатов хранит в томе Compose. PostgreSQL, Redis и Django доступны только внутри сети Compose.

Подготовьте отдельный закрытый S3-совместимый бакет. Сервисной учётной записи нужны чтение, запись и удаление объектов. Для первой приёмки используйте тестовые данные и отдельного Telegram-бота.

## Настройка и первый вход

1. Распакуйте дистрибутив в отдельный каталог. Выполните команды из его корня, подставив свои домен, адрес хранилища и бакет. Скрипт запросит ключи S3 скрытым вводом.
2. Сохраните защищённую копию `SECRET_KEY`, `TOKEN_ENCRYPTION_KEY` и `ACCOUNT_ENCRYPTION_KEY`. При переносе они нужны для работы с сессиями, токенами Telegram и двухфакторной защитой.
3. Проверьте состояние сервисов. Контейнер `migrate` должен завершиться с кодом 0, а база, API и обработчики должны запуститься.

```sh
python3 infra/configure.py --domain desk.example.com --s3-endpoint https://s3.example.com --s3-bucket service-desk
docker compose config --quiet
docker compose up --build -d
docker compose ps --all
docker compose logs --tail=100 migrate backend worker web
```

Создайте одноразовый код в контейнере API и прочитайте его в своём терминале. Откройте HTTPS-адрес организации, введите код и создайте аккаунт владельца с email и собственным паролем. После входа удалите файл с уже использованным кодом.

```sh
docker compose exec backend python manage.py prepare_installation --output /home/desk/installation-code.txt
docker compose exec backend cat /home/desk/installation-code.txt
# После завершения мастера
docker compose exec backend rm /home/desk/installation-code.txt
```

Вход сотрудников организован через приглашения. Для писем с приглашениями и восстановления пароля настройте SMTP сервера организации. Центральный портал разворачивается отдельно, со своей базой, секретами и адресом. См. [режимы развёртывания](DEPLOYMENT-MODES.md).

Для рабочего пространства OwnDesk передайте `--domain team.owndesk.work` при запуске `infra/configure.py`. Скрипт задаст `DOMAIN=team.owndesk.work` и HTTPS-адрес в `PUBLIC_BASE_URL` и `CSRF_TRUSTED_ORIGINS`. При прямом размещении направьте DNS-запись поддомена на рабочий сервер. `owndesk.work` используется центральным порталом.

После запуска проверьте адрес в разделе «Настройки → Сотрудники → Пригласить сотрудника». Выпустите новые приглашения для сотрудников, которым ранее отправляли ссылку с `127.0.0.1`. Откройте тестовую ссылку с другого ПК через отдельную сеть, примите приглашение и повторно войдите по email и паролю.

## Перенос существующей организации с Windows

Снимок `Local-Data.ps1 backup` содержит SQLite, вложения и ключи. Для Linux нужны перенос данных в PostgreSQL и загрузка вложений в закрытый S3-бакет с сохранением имён объектов. Восстановление снимка через `Local-Data.ps1 restore` предназначено для Windows.

Перед переключением сделайте снимок остановленной организации и проверьте перенос в отдельной базе и бакете. Для действующих интеграций и 2FA понадобятся прежние ключи шифрования. Сверьте количество сотрудников, обращений и вложений, проверьте открытие файлов и вход владельца со стойким паролем. При финальном переносе остановите старую запись и обработчик Telegram до запуска обработки на новом сервере.

## Приёмка на целевом сервере

- Из внешней сети проверьте перенаправление HTTP на HTTPS, доверие к сертификату и ответ 200 от обоих URL проверки. Используйте обычную проверку сертификата без отключения TLS-проверок.
- Войдите владельцем, пригласите тестового сотрудника и проверьте вход и загрузку вложения. В «Настройки → Состояние системы» дождитесь актуального сигнала worker.
- Подключите отдельного тестового Telegram-бота. Проверьте входящее обращение, ответ оператора и скачивание медиа.
- Сделайте резервную копию и восстановите её в отдельный Compose-проект и отдельный бакет. Сверьте обращения и вложения. См. [резервное копирование и восстановление](OPERATIONS.md).

```sh
curl -I http://desk.example.com
curl -fsS https://desk.example.com/api/v1/health/live
curl -fsS https://desk.example.com/api/v1/health/ready
docker compose exec backend python manage.py check --deploy
```

Проверка `ready` подтверждает доступ API к базе. Работу Redis, фоновых задач и S3 проверяйте по пользовательским сценариям выше.


На отдельном локальном стенде Caddy 2.10.2, Daphne и PostgreSQL 17.11 проверены перенаправление на HTTPS, цепочка тестового сертификата, защищённые cookies, мастер настройки и вход приглашённого сотрудника. Прокси WebSocket проверен с тестовым слоем каналов в памяти. На PostgreSQL прошли 79 тестов. Полный запуск Compose, публичный сертификат и Redis остаются в приёмке на Linux.
